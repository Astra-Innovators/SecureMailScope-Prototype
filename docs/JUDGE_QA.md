# Likely Judge Questions

### Q1. Where is AI?
AI is used after verified session features are extracted. RandomForest classifies risk and IsolationForest detects anomalous TLS behavior. The UI exposes the features and model output.

### Q2. Where is blockchain?
The prototype uses a local SHA-256 hash chain for forensic evidence integrity. Each record links to the previous record and includes evidence/report hashes. This is a tamper-evident ledger, not a claim of a public blockchain.

### Q3. Why not use blockchain for email encryption?
That would be unnecessary. TLS protects communication. Blockchain is better suited here for integrity/auditability of forensic evidence and reports.

### Q4. Is the AI trained on NTRO data?
No. The PS does not supply a labeled dataset in this prototype. The bundled ML model is trained on synthetic feature vectors and should be described honestly as a prototype model. With an official labeled dataset, it can be retrained.

### Q5. How do you avoid false AI findings?
The security findings are generated by deterministic rules from observed/verified features. AI is used for classification, anomaly detection, prioritization and explanation rather than fabricating packet evidence.

### Q6. How do you handle encrypted traffic?
The system is passive. It analyzes the TLS metadata and certificate bytes that are actually visible in the PCAP. It does not decrypt protected application payloads. For TLS 1.3, certificate messages are normally encrypted after ServerHello, so passive X.509 extraction requires session keys.

### Q7. What does STARTTLS detection mean?
The parser searches observed application data for STARTTLS indicators and checks whether a visible TLS transition follows.

### Q8. What is Forward Secrecy?
A property where ephemeral key exchange limits the impact of compromise of a long-term private key on past sessions. ECDHE/DHE are common mechanisms.

### Q9. What happens if there is no certificate in the PCAP?
The dashboard marks certificate fields as not observed/not extracted and the system does not invent certificate details. This commonly occurs with TLS 1.3 passive captures because the certificate handshake is encrypted.

### Q10. What is the main novelty?
Combining passive email-protocol forensics, cryptographic posture scoring, explainable ML/anomaly detection, prioritized remediation and tamper-evident evidence integrity in one analyst workflow.
